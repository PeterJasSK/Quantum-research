## Provenance of the data — the 2026-08-03 model fix (methodological facts the paper states honestly)

The data this paper defends comes from a race model **corrected on 2026-08-03**. Methods and
Threats-to-Validity must describe the *corrected* model:

1. **Continuous-flood, analytic per-window race.** The original engine enumerated every forged packet
   across `[0, max_t_auth]`; with ~500 ms retransmit gaps and ~20 ms live windows, ~95 % of packets
   fell in dead gaps (no cliff, billions of ops). The corrected engine evaluates each *live* window
   analytically: `g_live = send_rate · window_duration` distinct guesses land in it; it is poisoned
   with probability `g_live / S` (`S = 2^effective_bits`). O(windows), not O(packets).
2. **The analytic anchor.** The whole race reduces to `P = 1 − (1 − g_live/S)^W`,
   `W = r · q · attempts`. The Monte-Carlo sim tracks this closed form within **max |sim−anchor| =
   0.008** at 1500 trials/cell — the paper's simulator-correctness argument.
3. **Realistic send-rate + Kaminsky campaign.** Send-rate is **100 000 pps** (realistic); one 20 ms
   window fires only `g_live ≈ 2^11`. The attacker's power is a sustained Kaminsky campaign of
   `ATTACK_ATTEMPTS` fresh-query windows (folded analytically, O(1)); the default puts the knee at
   **eff ≈ 24**, i.e. **≈ 8 388 windows ≈ 168 s of flooding** to reach `2^24` guesses. A citable
   attacker-cost result.
4. **Per-source effective search space (`source_model.py`).** Nominal effective bits = x-axis; the
   attacker's real search shrinks for weak sources: `fixed` = known port ⇒ search = `txid_bits`
   (flat-poisonable); `prng` = state-recoverable ⇒ a fixed `PRNG_LEAK_BITS = 6` discount (cliff 6
   bits right of CSPRNG); `csprng`/`qrng` = full. Ordering **fixed ≥ prng ≥ csprng ≈ qrng**.
5. **The null result is EXACT.** The engine is source-agnostic (§3.5): the outcome depends on `S`
   and the seed-driven guess order, **not on the draw's bytes**. So `csprng` and `qrng` at matched
   bits + seed are **byte-identical** (`cliff-csprng-24 = cliff-qrng-24 = 0.6290`), not merely
   overlapping. Frame as *"at matched effective entropy, source pedigree buys zero rate reduction;
   QRNG's value is the attestable receipt (M5)"* — never "we forgot to use the quantum entropy." The
   receipt is the real quantum artefact; the security is the entropy count.

   SAD-DNS knob, Kaminsky campaign at a realistic 100 kpps); the headline (cliff at ~24 effective
   bits; csprng ≡ qrng); and the QRNG-provenance framing (AC-7.3), stated as an honest null result.
2. **Introduction** + `Research Question` / `Objectives` / `Contributions` subsections (example
   style). RQ: *does DNS cache-poisoning success depend on the randomness source, or only on the
   effective entropy bits — and what does a QRNG add if not a lower rate?* Contributions: the cliff
   quantified across sources; the source-effective-entropy model (fixed known-port collapse, weak-RNG
   discount); the exact null result; the Kaminsky attacker-cost reading; the provenance mechanism;
   the open reproducible harness + web demo.
3. **Background & Threat Model.** Kaminsky, RFC 5452 port randomisation, SAD-DNS. Threat model
   verbatim from epic §6 (off-path, bounded send-rate, can trigger resolutions) and the three
   deployment scenarios (legacy fixed-port 16-bit; RFC 5452 up to ~32-bit; RFC 5452 under SAD-DNS
   `32 − k`), each crossed with four sources.
4. **Research Methodology** + **Scale/Model Caveat** (example §III-C analogue). The race state
   machine (epic §5), the acceptance rule `guess == target ∧ t_event < t_auth`, the four sources, the
   SAD-DNS `effective_bits = txid + max(0, port − k)` knob, `source_model.attacker_search_bits`, the
   Kaminsky-campaign flood, and the analytic anchor `P = 1 − (1 − g_live/S)^W` as the correctness
   reference. Caveat: simulated discrete-event model (§3.4), source-agnostic engine ⇒ the null result
   is structural.
5. **Implementation.** The frozen `testbed/` components described (engine, sources, SAD-DNS,
   `source_model`, portable PRNG, `QRNGClient`), with an `algorithm` block for the per-window
   campaign fold (mirror the example's `algorithm` environments). No code changes — description only.
6. **Experimental Results** (`booktabs` table + Fig. 1 + Fig. 2).
   - **M1 entropy cliff (Fig. 1, headline, AC-7.2).** `fixed` flat ≈ 1.0; `prng` cliff ~30 bits;
     `csprng`/`qrng` cliff ~24 bits, overlapping; sim-vs-anchor max dev 0.008. Representative table
     below.
   - **M4 SAD-DNS collapse (Fig. 2, AC-7.2).** csprng poison vs leaked `k` (eff 32→16): 0.003 → 1.0,
     monotone.
   - **M3 birthday amplification.** Amp vs `q` at eff 28: ×1 → ×10.8 for `q = 1…16` (~×q, anchor
     ×10.43).
   - **M2 attacker cost.** Mean forged packets / time-to-poison; the ~168 s-to-knee campaign reading.
   - **M5 provenance (AC-7.3).** Real 232-char Q-EaaS signed receipt (`request_id`, `entropy_epoch`,
     `receipt`, `endpoint`); PRNG `seed`+`draw_index`; CSPRNG a source note.
7. **The Entropy-Cliff / Attacker-Cost Specification** (dedicated section, the DNS analogue of the
   example's "Rotation-Frequency Specification"). Derive the campaign-cost reading: to poison an
   `n`-effective-bit resolver an off-path attacker needs `W ≈ 2^n / g_live` live windows ≈
   `2^n / (send_rate · RTT)` — at 100 kpps, RTT 20 ms, that is ~168 s for `n=24`, ~12 h for `n=32`.
   An operator-facing bound: *each effective bit above the knee multiplies the attacker's required
   campaign time by ~2*. State it as the actionable output (matching how the example turns its model
   into a cadence rule).
8. **Discussion.** Answering the RQ (source-independent at matched entropy); the exact-null-result
   framing (AC-7.3) handled head-on; practical QRNG-as-a-service value = auditable, signed provenance
   for compliance-sensitive multi-tenant resolvers (reuse the example's §Discussion argument);
   positioning (epic §10). Then **Limitations** and **Future Work** subsections (example style).
9. **Threats to validity (AC-7.4)** — fold into Limitations: epic §6 out-of-scope (on-path, DNSSEC,
   DNS-0x20 case encoding [Dagon 2008 — *additional* entropy not modelled], DoT/DoH, multi-upstream,
   rate limits), plus this session's modelling choices (`PRNG_LEAK_BITS = 6` abstracts state
   recovery, not a specific MT attack; OS ephemeral-port range ~11–16 bits [epic OQ-1] can push the
   practical floor below 16; source-agnostic engine ⇒ the sim does not *exercise* the quantum entropy
   in the outcome — the receipt is its artefact).
10. **Conclusion + Acknowledgment.** Entropy bits are the defence; provenance is the QRNG's job.
