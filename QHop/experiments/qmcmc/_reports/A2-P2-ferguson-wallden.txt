1. THE CGQeMCMC ALGORITHM, EXACTLY AS GIVEN
-----------------------------------------------------------------------------
1.1 Base QeMCMC as P2 states it [P2 Sec II.D, p4, Eqs 6-9, Algorithm 2]
  Eq 6:  H = (1 - gamma) * alpha * H_prob + gamma * H_mix,  H_mix = sum_j X_j.
  Eq 7:  H_prob = - sum_{j>k} J_jk Z_j Z_k - sum_j h_j Z_j = sum_s E(s)|s><s|.
  Eq 1:  E(s) = - sum_{j>k=1}^n J_jk s_j s_k - sum_{j=1}^n h_j s_j  [p2].
  Eq 2:  mu(s) = e^{-E(s)/T} / Z  [p2]  -> temperature T is used throughout, never beta.
  U = e^{-iHt}, "with practical implementation requiring an approximation through the
  Trotter-Suzuki product" [p4].
  Eq 8:  Q(s'|s) = |<s'|U|s>|^2 = |<s|U|s'>|^2 = Q(s|s')  ("symmetry constraint").
  Eq 9:  A(s'|s) = min(1, exp((E(s) - E(s'))/T)).
  Algorithm 2 (p4): "gamma <- hyper-parameter in range (0.25, 0.6); t <- hyper-parameter
  in range (2, 20); |psi> <- exp[-iHt]|s>; s' <- X measurement result of |psi>".
    [INFER] "X measurement" in line 5 conflicts with the text ("Measurement in the
    computational basis state returns a binary outcome", p4); most likely a typo.
  alpha: appears in Eq 6 but its value / normalisation rule is NOT given in P2 (not in P2).
  Quote [p4]: "hyper-parameters are sampled in the range t = (2,20) and gamma = (0.25,0.6),
  although optimization of these parameters is an ongoing issue."
  Quote [App A p12]: "gamma is varied in the range (0.25, 0.6) and the integer time
  parameter is varied between (2, 20) for all of the following experiments."  -> t is an
  INTEGER drawn from 2..20.

1.2 Coarse-graining framework [P2 Sec III.A, p5, Algorithm 3]
  Quote: "This is immediately realized in Ising models at each MCMC step by isolating a
  group consisting of q spins - here referred to by the corresponding fraction of the
  lattice per group (q/n). These spins may not necessarily be close to one another or even
  interact, however the optimal (in terms of thermalization) choice of spins in a group is
  likely to depend on the details of the problem."
  Algorithm 3 (Coarse Graining): s' <- s; index <- find spins in group; s_g <- subset of s;
  s'_g <- QeMCMC(s_g) [Algorithm 2]; s'[index] <- s'_g.  Only group spins change.
  Acceptance is not written inside Algorithm 3; Algorithm 1 (p3) and Eq 9 (full E(s), full
  mu) are the accept rule. [INFER] => MH uses the FULL n-spin energy, so the reduced
  Hamiltonian only shapes the proposal.

1.3 Strategy (a) Naive local group [P2 Sec IV.A, p6, Eq 13]
  Quote: "pick the indices of spins that are neighbors forming the set,
  g_l = {i_r, i_{r+1} ... i_{r+q}} where i_r is the index of a randomly selected spin s_r
  that begins our 'local group'."
  [INFER] as written the set has q+1 elements (index notation slip); wrap-around at the
  end of the index list is not specified (not in P2).
  "Local" = consecutive INDICES, not physical locality: "We still use the term 'local' to
  distinguish this coarse graining strategy from others, but this should not be
  misunderstood as 'physically' local." (p6)
  Eq 13: J~ = J_{i in g_l, j in g_l},  h~ = h_{i in g_l}.  "This new Hamiltonian
  represents only the selected spins, while essentially ignoring the spins not selected."

1.4 Strategy (b) Improved local group = effective local field [P2 Sec IV.B, p6-7, Eqs 14-15]
  EXACT FORMULA (Eq 14, p6):
        h~_j = h_j + sum_{i not in g_l}^{n} J_ji s_i        (for each j in g_l)
        J~   = J_{i in g_l, j in g_l}  (unchanged from naive)
  "Where each s_i (value of spins not in the group) is now a constant parameter."
  Eq 15 (p7): sum_{j in g_l} h~_j s_j = sum_{j in g_l} s_j (h_j + sum_{i not in g_l} J_ji s_i).
  Hamiltonian on QPU [INFER from Eqs 6,7,13,14]:
        H_g = (1-gamma)*alpha*( - sum_{j>k in g} J_jk Z_j Z_k - sum_{j in g} h~_j Z_j )
              + gamma * sum_{j in g} X_j ,   on q qubits.
  Quote (p7): "In this way, the accuracy of the Hamiltonian is increased from the local
  group method without the addition of any quantum gates. The effective Hamiltonian
  H'_prob now fully represents the relative energy of any two states of the group."
  Quote (p7): "improved local grouping refines the naive local groups, however there is
  still tail-off for small q/n."
  [INFER] Correct: E(s_g, s_rest) = E_g^eff(s_g; s_rest) + const(s_rest), so energy
  differences between two group configurations are exact. The ZZ graph on the QPU is the
  induced subgraph of J on g (all-to-all q-qubit for a fully connected SK-like J).

1.5 Strategy (c) Multiple groups / "multiple sampling" [P2 Sec IV.C, p7, Algorithm 4]
  Quote: "we use sqrt(n) groups of size sqrt(n). This method can be easily combined with
  the improved local group method resulting in an iterative process that loops through the
  entire lattice where each quantum computation inherits the measurement results of the
  last."
  Quote: "we first split the spins into our sqrt(n) local groups before evaluating the
  first group individually using the Improved local group method. The measurement results
  of this group then update the state of the system, impacting the environment of the next
  group which is subsequently evaluated using the Improved local method. In this way, our
  algorithm iterates through the groups, where at each step the measurement results update
  the system for subsequent groups' update. The MH acceptance is only computed after the
  entire state has been updated by each of the sqrt(n) groups. For the remainder of the
  paper, this method will be labeled 'multiple sampling' and will harness the Improved local
  group strategy."
  Algorithm 4: "for i <- 0 to n_g do: index <- spins in i-th group; s_g <- subset of s
  using index; s'_g <- QeMCMC(s_g); s'[index] <- s'_g".  -> FIXED order 0..n_g-1.
  [INFER] Algorithm 4 literally builds s_g from s (not s'), but the prose says each group
  sees the updated environment; the prose is the intended method. Whether the partition is
  fixed or re-randomised each MCMC step is NOT stated (not in P2); the remainder discussion
  (V.A, p7: "If we have n = 10 and q = 6, the remainder is 4, meaning an optimal multiple
  sample strategy with q = 6 also has another 4 qubit quantum computation") suggests a
  fixed contiguous-block partition with a remainder block.
  Quote (p7): "With this CG we are able to maintain both advantages of QeMCMC described at
  the start of the section: can jump to arbitrary Hamming distances; use the full problem
  Hamiltonian for these jumps."
  [INFER] Caveat: "full problem Hamiltonian" only in the mean-field/conditional sense: each
  group sees a classical frozen environment; no cross-group coherent dynamics.

1.6 Qubits, sweeps, parallel QPUs
  - Qubits per QPU call = q (group size); headline q = sqrt(n) [P2 Sec IV.C p7; abstract].
  - Sweep: in multiple sampling, one MCMC step = one pass over all n_g = sqrt(n) groups,
    sequentially, then ONE MH accept/reject on the whole new state [P2 p7].
  - Parallel QPUs: claimed as a framework property: abstract/intro p1: "each subset 'group'
    of the lattice can be evaluated in separate quantum computations, even on different QPUs
    in parallel"; p2 contributions: "in some cases, parallelize computation over multiple
    QPU." No parallel experiment is reported (not in P2).
    [INFER] The best strategy (multiple sampling + improved field) is inherently SEQUENTIAL
    (each group's field depends on the previous group's measured output), so it cannot be
    run in parallel as specified. Parallelism is only consistent with naive groups (no
    environment dependence) or with a graph-colouring scheme (non-interacting groups) that
    P2 does not discuss.

3. DETAILED BALANCE / PROPOSAL SYMMETRY
-----------------------------------------------------------------------------
What P2 says:
  - Eq 5 (p3): detailed balance P(s'|s)mu(s) = P(s|s')mu(s').
  - Eq 8 (p4): symmetry of the QeMCMC proposal -> Eq 9 acceptance with no proposal ratio.
  - Irreducibility/aperiodicity: "These are true in our case as no states are forbidden
    assuming there is no unwanted symmetry as discussed in [9]." (p3)
  - The ONLY CG-specific statement (Sec VI, p11): "A Markov chain produced by the CGQeMCMC
    provably samples the Boltzmann distribution as it satisfies detailed balance and is
    aperiodic and irreducible."  NO proof, no derivation, no per-strategy argument, no
    acceptance-ratio correction anywhere in P2.
  - Group-selection probability: P2 never discusses it explicitly. Group choice is "a
    randomly selected spin s_r that begins our 'local group'" (p6) => state-independent.
    State-dependent group choice: not in P2.

My analysis [INFER, all of the following]:
  (a) Naive group, random start r (state independent), U_g built from J~,h~ only.
      H_g is real-symmetric in the Z basis (ZZ, Z diagonal real; X real symmetric) so
      U_g^T = U_g and |<a|U_g|b>|^2 = |<b|U_g|a>|^2. Mixture over r, t, gamma of symmetric
      kernels is symmetric. Spins outside g unchanged. MH with full E => detailed balance OK.
  (b) Improved group: h~ depends on s_rest, but s_rest is identical in s and s' (only g
      changes), so the SAME U_g governs s->s' and s'->s. Symmetric. Detailed balance OK
      provided group choice is state independent (it is).
  (c) Multiple sampling with FIXED order g_1..g_m and a single MH at the end:
      Q(s'|s)  = prod_i |<s'_{g_i}| U_i(env_i)  |s_{g_i}>|^2, env_i  = (s'_{g<i}, s_{g>i})
      Q(s|s')  = prod_i |<s_{g_i}| U_i(env'_i) |s'_{g_i}>|^2, env'_i = (s_{g<i}, s'_{g>i})
      env_i != env'_i in general (for i>1 and i<m), so the effective fields differ and
      Q(s'|s) != Q(s|s') in general. Eq 9 (ratio = 1) is then NOT justified; the chain's
      stationary distribution can be biased away from Boltzmann. P2's "provably ... satisfies
      detailed balance" is therefore a GAP for its headline method. (Holds trivially only if
      groups do not interact, i.e. J between groups = 0.)
      Fixes (mine): (i) choose the sweep order sigma at random with P(sigma) = P(reverse
      sigma) (e.g. forward/backward with prob 1/2): then Q_sigma(s'|s) = Q_{rev sigma}(s|s')
      exactly (the reverse sweep sees env (s'_{g<i}, s_{g>i}) at group i), so the mixture is
      symmetric; (ii) do an MH accept/reject after EACH group (Metropolis-within-Gibbs: each
      group kernel is reversible, the sweep composition preserves Boltzmann, though the
      composite is not reversible); (iii) compute the Hastings ratio explicitly (costly:
      needs |<a|U|b>|^2 for each group, exp in q classically).
  P2's own spectral-gap numbers for (c) come from a P matrix estimated by brute force
  (App A p12: "randomly select a starting state, run a CGQeMCMC step where t and gamma are
  randomly chosen and then add 1/n_s to the (i,j)th element of Q ... n_s = (2^n)^2 deemed
  fit"). [INFER] If Q is asymmetric and A from Eq 9, that P's stationary vector is not mu;
  the gap delta = 1 - max_{lambda!=1}|lambda| (Eq 11) would then be the gap of a chain
  converging to the wrong distribution. P2 never checks the stationary vector of P.
  Convergence plots at n=16-36 do not settle it either (at T=0.1 no method converged).
  State-dependent group choice (e.g. "strongest-coupling to currently frustrated spins"):
  [INFER] would require the Hastings factor P(g|s')/P(g|s); not discussed in P2.

    statevector emulations in qulacs (App A p12: "run the appropriate quantum circuit and
    output the statevector"); Trotterisation only mentioned generically (p4).
  - Executions per MCMC step: QeMCMC is "one-shot ... requiring only a single execution on a
    QPU per step" (p1). [INFER from Algorithm 4] multiple sampling = n_g = sqrt(n) sequential
    single-shot q-qubit executions per MCMC step (plus a remainder block for non-square n);
    naive/improved single group = 1 execution per step.
  - Connectivity: abstract: "adaptable to various quantum hardware specifications - in
    particular those with limited connectivity." [INFER] for fully connected J each group
    needs all-to-all ZZ among q qubits; P2 gives no compilation/SWAP counts.
  - Classical cost of building h~: [INFER] O(q(n-q)) per group, trivial.

8. CLASSICAL SIMULABILITY / "quantum-inspired" (exact quotes)
-----------------------------------------------------------------------------
  - Footnote [12] (p11): "Here we need to stress that by quantum speed up we mean that our
    proposal outperforms the classical MCMC. It is understood, that while the size of the
    quantum computer used is small, and specifically smaller than what can be classically
    simulated, the advantage of our algorithm can be viewed as a 'quantum inspired'
    approach, while the true quantum advantage can be achieved when the QPU used is larger
    than what can be classically simluated." [sic]
  - p2: "In both cases, the quantum computers part of CGQeMCMC is realised in an emulation
    environment (using classical devices - see Appendix A for details of the
    implementation)."
  - Abstract: "it requires very few qubits to approach classically intractable problem
    instances".
  - p1: QeMCMC "is expected to exceed quadratic scaling in comparison with the best classical
    alternative in certain contexts".
  [INFER] At q = 6..18 the proposal is trivially classically simulable; by the authors' own
  footnote the 36-spin results are a quantum-inspired classical algorithm. Genuine quantum
  advantage would require q > ~50, i.e. n > ~2500 under q = sqrt(n).

-----------------------------------------------------------------------------
9. WHAT IS LOST, LIMITATIONS, OPEN QUESTIONS
-----------------------------------------------------------------------------
  Lost vs full QeMCMC [P2 p6]:
   - "Firstly, the Hamming distance of proposal steps is fundamentally restricted to the
     size of the group. While this is better than classical local move approaches, it still
     puts a bound on the jumps that the proposal steps can make, and is more likely to get
     stuck in local minima".
   - "The second issue is that the new problem Hamiltonian H'_prob is missing contributions
     from the ignored spins making the evolution fundamentally incomplete." (naive)
   - "If one were to consider a 1D Ising model where only neighboring spins interact, this
     choice of CG is likely to perform adequately, as the boundary interaction terms of the
     group is constant (2) with cluster size ... The same is not true for general Ising
     models with higher connectivity."
   - Numbers: multiple-sample k worse than QeMCMC at every T (0.46 vs 0.25; 0.50 vs 0.335;
     0.10 vs 0.087; Table I). Single-group CG loses speedup at most T for n=9 (Fig 2 text).
   - Fig 4 caption (p10): "The more local a proposal, the larger the offset from the true
     average energy (black line). This is greatly reduced by CGQeMCMC with multi-sampling
     and larger groups - methods that decrease the locality of proposals."
   - p10: CG proposals "also occasionally suffer from local minima."
   - [INFER] No coherent superposition across groups: the proposal is a product of
     independent q-qubit unitaries conditioned on classical outcomes, so cross-group
     "tunnelling" is only via sequential classical conditioning.
  Limitations stated: spectral gap only to 10 spins (p2); fully connected only; no noise;
  few instances at large n; magnetization not converged; spectral gap ignores multi-chain
  schemes (p5); uniform proposal result misleading ("Figure 3 may wrongly suggest that the
  uniform proposal is a useful step", p9).
  Open questions (quotes):
   - NOISE (p10-11): "The effect of noise has not been investigated. The QeMCMC method is
     by construction noise-resilient, and our CG approach uses smaller QPUs minimizing
     further these effects. Concrete analysis for the level and types of noise under which
     we maintain the quantum scaling advantage is an important open question. Here it is
     also worth pointing out that due to the one-shot nature of the algorithm, standard
     error mitigation methods are not applicable meaning it would require a bespoke scheme
     that is outwith current literature [36, 37]."
   - Sampling error / autocorrelation (p11): "Another future direction is quantification of
     the sampling error induced by coarse graining. ... Speeding up thermalization does not
     necessarily result in quicker auto-correlation, and thus this must be studied in future
     work to properly understand the cost of coarse graining compared to the QeMCMC."
   - Beyond Ising (p11): "An important future step is to apply coarse graining to problems
     other than the Ising model. Application of variationally prepared Hamiltonian evolution
     is also an interesting avenue ... apply the CGQeMCMC to quantumly enhance classical
     methods such as simulated annealing, parallel tempering and population annealing."
   - Hyper-parameters: "optimization of these parameters is an ongoing issue." (p4)
   - Grouping: "the optimal (in terms of thermalization) choice of spins in a group is
     likely to depend on the details of the problem" (p5); improved-group energy artefact
     "Scaling of this artifact is left to future work." (p13)
   - Unproven detailed balance for multiple sampling (my finding, section 3) - not raised
     by P2.

-----------------------------------------------------------------------------
10. TUNING GROUP SIZE TO HARDWARE
-----------------------------------------------------------------------------
  Yes, explicitly claimed, with only the 36-spin q=6/12/18 runs as evidence:
   - p9: "This highlights the flexible nature of this coarse graining algorithm, that can
     take as input the size of the hardware that one has and accordingly achieve the best
     possible performance."
   - p10: "The choice of q = sqrt(n) qubits in this paper was successful, however the
     optimal relation between q and fastest thermalization or indeed autocorrelation is both
     problem and hardware dependent. Future work should use the CGQeMCMC to exploit the
     connectivity of hardware. For example, if one were to consider an Ising model with 3D
     connectivity, they could partition the problem into n planar lattices that are suitable
     for the 2D connectivity common to many QPU. In this way, the CGQeMCMC can be a powerful
     tool in relating highly connected problems to QPUs with limited connectivity."
   - Abstract: "adaptable to various quantum hardware specifications - in particular those
     with limited connectivity." ; "Our method can be easily combined with other classical
     and quantum techniques".
   - Fig 1 (q/n sweep at n=6,8,10, T=1) is the only systematic q-dependence data: gap
     decreases as q/n decreases, much faster for naive groups.
  [INFER] No q-vs-noise trade-off, no hardware-connectivity-aware grouping, and no
  per-group compilation cost is studied.

DECISION-RELEVANT SUMMARY (top facts)
-----------------------------------------------------------------------------
 1. Effective field (Eq 14, p6): h~_j = h_j + sum_{i not in g} J_ji s_i; J~ = J restricted to
    g (Eq 13). Exact for energy differences within the group.
 2. Only 3 strategies, all index-contiguous groups, random start; strongest-coupling /
    cluster / state-dependent groups not studied (p5-6).
 3. Best method = sqrt(n) groups x sqrt(n) qubits, sequential sweep with field update, one MH
    accept at end (p7, Alg 4) -> sequential, not parallel.
 4. Detailed balance asserted without proof (p11); my derivation: OK for single groups,
    NOT generally OK for fixed-order multiple sampling with Eq 9 (no Hastings correction).
    Fix: random forward/reverse order or per-group MH.
 5. k at T=1: uniform 0.97, local 0.92, QeMCMC 0.335, naive 0.77, improved 0.64, multi 0.50
    (n=4..10, Fig 3); k_QEF 1.84 (T=1), 2.17 (T=0.1), 2.6 (T=10).
 6. Low T: single-group CG worse than uniform (Table I 1.27/1.1 vs 1.003); only multiple
    sampling holds; Table I header "0.01" vs figure "0.1" inconsistency.
 7. sqrt(n) evidence = noiseless statevector, n<=10 fits (only n=4,9 exact sqrt(n)) + one
    instance each at n=16/25/36, 20 chains; nothing converged at n=36, T=0.1.
 8. J/h distribution, alpha, circuit depth, Trotter steps, shots, autocorrelation: not in P2.
 9. Footnote [12]: small-q advantage is "quantum inspired".
10. Noise: "Concrete analysis for the level and types of noise ... is an important open
    question"; one-shot => standard error mitigation not applicable.
