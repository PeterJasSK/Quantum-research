# Quantum Phantoms: reverse engineering (AI entry point)

Read this first if you are an agent starting work here. Humans: open [`about.html`](about.html) (explainer)
and [`index.html`](index.html) (browser over all letters and targets).

## Purpose

Reverse-engineer 21 published methods that each solve part of the Quantum Phantoms pipeline. For each one:
dissect the paper, reproduce one published number, then rebuild it standalone, adapted to lungs, certification
and signing. The work is **independent of the MVP** (`QuantumPhantoms/code/` is never imported), **simulation
only** (AerSimulator ideal + `FakeMarrakesh` Heron-class noise, with no IBM jobs), and **fully 3-D** (2-D slices are
a final export only). Plan: [`epic-reverse-engineering.md`](epic-reverse-engineering.md). Targets:
[`reverse-engineering-targets.md`](reverse-engineering-targets.md). Papers: `../papers/<code>_*.pdf` (local only).

Pipeline: **A** placement → **B** rulebook + CT context → circuit → **C** certificate → **D** quantum growth →
**E** classical growth → **F** render into CT → **G** sign / provenance → **H** analysis.

## Run conventions

- Working directory = this folder; Python = conda base (`/home/peter/anaconda3/bin/python3`, 3.13).
- Everything is a module: `python -m shared.validate --stubs`, `python -m A_placement.src.<module>`.
- Letters import only `shared` (helpers documented in [`shared/README.md`](shared/README.md)), never each other.
- Every run goes through `shared.runrecord.start_run(...)` into `<L>/runs/`, which is gitignored.
- Seed every PRNG with `shared.seedhash.rng(certificate["extracted_seed_hex"], "<L>.<purpose>")`.
- No automated tests (repo directive). Verification is manual plus the paper reproduction in `repro/`.

## Honesty gates

- Every quantum deliverable states its claim level (`L0` provenance, `L1` entangled generative state,
  `L1′` memory advantage), ships with its classical baseline, and has its belief-propagation simulability number (#9).
  There is no L2/L3 claim.
- Every quantum number is labelled `simulated: ideal` or `simulated: Heron-class noise (FakeMarrakesh)`. The schemas enforce it.
- Simulated CHSH certifies nothing: certificates say `certification-ready, not certified (simulated)`.
  S ≤ 2 means `fail`, no seed, the draw rejected and logged (no retry, no fallback).
- A single-qubit dial read in Z is a classical biased coin. Interference claims need multi-qubit correlations
  read in ≥ 2 bases.
- Never claim "more realistic because quantum", "quantum biology", or "classically impossible".
- Privacy-by-construction: no patient voxels enter a generator, only fitted parameters and published statistics.

## Parallel sessions (ownership rules)

- One git worktree + branch per letter: `git worktree add ../qp-re-<L> -b re-<L>`. Never run two sessions in one checkout.
- A session writes **only** inside its own `<L>_<name>/` folder and its own `feature-<L>-<name>.md`.
- It never edits `shared/`, the epic, the targets list, `about.html`, `index.html`, `site/`, `.gitignore`,
  or another letter's folder.
- If you need a contract change, record it under "Contract change requests" in your letter README, adapt locally, and keep going. INT applies it.
- You may run `python -m shared.site.build` to preview, but **do not commit `index.html` / `site/`**.
  Do not run `--update-readme` either.
- Workflow: `/plan-feature <L>` → review → `/implement-feature` → merge the branch to `main`.
- Waves: W → {A, C, E, F} → {B, D, G, H} → INT. Run about 4 sessions at a time.
